# 统计、身体数据与智能建议模块说明

## 1. 数据统计

统计逻辑统一放在后端 `StatisticsService`，前端只负责展示，避免前后端各算一套。

| 接口 | 说明 |
|---|---|
| GET `/api/stats/overview?weeks=12` | 总训练量、完成组数、计划完成度、每周频率/训练量、部位有效组数、动作统计 |
| GET `/api/stats/exercises/{id}/trend` | 指定动作的 e1RM 与训练量趋势、PR |
| GET `/api/stats/weight` | 体重与 7 日移动平均 |
| GET `/api/stats/calendar?year=&month=` | 训练日历 |

统计口径：

- 训练量 = `Σ(重量 × 次数)`，只统计正式组且已完成。
- 训练频率按“有已完成组的训练日”去重，同一天训练多次计 1 次。
- 部位有效组数 = `Σ(组数 × 部位权重)`，主动肌 1.00、协同肌 0.40；单侧动作每侧计 0.5 组。
- e1RM 使用 Epley 公式，仅计算 1—10 次的次数类动作。
- 计划完成度 = 已完成正式组数 ÷ 计划组数。

## 2. 身体数据

- GET `/api/metrics`：分日期范围查询体重、体脂率和腰围。
- POST `/api/metrics`：新增或覆盖某一天的记录（一天一条）。
- DELETE `/api/metrics/{id}`：删除记录。

页面入口：`/metrics`。

## 3. 智能建议

采用“规则引擎先行、模型改写后置”的两段式设计。当前阶段只运行规则引擎，外部大模型接口保留在
`AiAdvice` 的 `model_name`、`prompt_version`、`fallback_used` 字段中，后续接入时不需要改动统计模块。

| 接口 | 说明 |
|---|---|
| POST `/api/advice/generate` | 生成一次建议，写入 `ai_advice` 和 `ai_advice_item` |
| GET `/api/advice` | 建议历史列表 |
| GET `/api/advice/{id}` | 建议详情，按 ALERT > WARN > INFO 排序 |
| POST `/api/advice/{id}/feedback` | 建议评分与反馈 |

已实现的规则：

`DATA_INSUFFICIENT`、`LOW_FREQUENCY`、`VOLUME_SPIKE`、`LOW_PLAN_COMPLETION`、
`MUSCLE_UNDERTRAINED`、`MUSCLE_OVERTRAINED`、`WEIGHT_STALL`、`PLAN_DEVIATION`、
`PAIN_FLAG`、`BODYWEIGHT_TREND`。

每条规则输出结构化 `Finding`，包含 `ruleCode`、`severity`、`title`、`evidence` 和建议文案。
数字由后端计算，规则结论不依赖模型，模型失败时直接使用规则模板，保证页面始终可用。

## 4. 管理端

页面入口：`/admin`（仅 ADMIN 角色可见）。

| 接口 | 说明 |
|---|---|
| GET `/api/admin/platform` | 平台数据概览 |
| GET `/api/admin/users` | 用户分页与搜索 |
| PUT `/api/admin/users/{id}/status` | 启用 / 禁用用户 |
| GET/POST/PUT `/api/admin/exercises` | 动作库查询、新增、修改 |
| PUT `/api/admin/exercises/{id}/status` | 归档 / 恢复动作 |
| GET `/api/admin/audit-logs` | 管理员操作日志 |

## 5. 系统模板与自由训练

- GET `/api/plans/templates`：系统计划模板列表。
- POST `/api/plans/{templateId}/copy`：把模板复制成当前用户的计划。
- POST `/api/sessions/free`：不关联计划直接开始一次自由训练。
