# 训练模块实现说明

训练模块完成“训练计划 → 开始训练 → 逐组记录 → 结束训练 → 历史回看”的闭环。

## 1. 数据链路

```text
workout_plan
  └─ plan_day
       └─ plan_exercise

workout_plan / plan_day
  └─ workout_session
       └─ session_exercise
            └─ workout_set
```

计划负责描述“准备怎么练”，训练记录负责保存“实际怎么练”。开始训练时，系统会把计划名称、
训练日名称、动作名称、计划组数、目标次数、目标重量和目标时长复制到训练记录中。之后修改计划，
不会改变已经生成的训练记录。

## 2. 页面入口

| 页面 | 路径 | 功能 |
|---|---|---|
| 训练计划列表 | `/plans` | 新建、查看、删除计划 |
| 计划详情 | `/plans/:id` | 按周添加训练日、添加和编辑计划动作、开始训练 |
| 训练记录列表 | `/sessions` | 查看进行中训练和历史训练 |
| 训练详情 | `/sessions/:id` | 逐组记录、加动作、替换、跳过、结束或取消训练 |

## 4. 关键业务规则

1. 一个用户同一时间只能有一条 `IN_PROGRESS` 训练。
2. 训练日至少有一个动作才能开始训练。
3. 训练开始后立即复制计划快照，历史记录不依赖后续计划修改。
4. 每组至少填写重量、次数或时长中的一项。
5. 只有 `phase = WORK` 且 `is_completed = 1` 的组计入完成组数、训练量和 e1RM。
6. 结束训练前至少需要一组已完成的正式组。
7. 已被记录组数据的动作不能直接标记跳过。
8. 训练结束后，组数据和动作信息只能查看，不能继续修改。
9. 单侧动作通过 `side = L/R` 分别记录，左右两侧共同组成一次完整训练。
10. e1RM 使用 Epley 公式，只计算 1—10 次的正式组。

## 5. 当前规范化处理

- 训练量：`Σ(weight_kg × reps)`，只统计已完成正式组。
- 动作 e1RM：`weight × (1 + reps / 30)`，保留两位小数。
- 组编号：同一动作同一侧从 1 开始，数据库唯一约束防止重复。
- 计划完成度：计划组数来自 `session_exercise` 快照，实际完成组数来自 `workout_set`。
